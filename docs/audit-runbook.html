Audit existujícího businessu Pneu 007

Legacy web, objednávky, kalendář a platební evidence existují před agentem a fungují bez aktivního rulebooku. Tento postup nesimuluje audit. Auditní návrh vytváří skutečný firemní GrokBot, majitel sám aktivuje jeho doloženou verzi.

Skutečný audit

  1. Spusťte legacy aplikaci. Ověřte, že getActive() odmítá neaktivní pravidla, zatímco lidský nákup funguje.
  2. Přihlaste skutečný firemní GrokBot jeho business-agent identitou. Dejte mu prompts/business-audit.md a URL. Načte GET /api/audit/sources, GET /api/audit/export/<source_id> a pseudonymizovaný export GET /api/audit/export/legacy-observations.
  3. Bot sám sepíše profil, parametry, evidence a findings. Každý parametr má citaci {source_id,version,hash,excerpt}. Úryvek musí prokazovat přesnou hodnotu, nestačí odkaz na nadpis.
  4. Bot odešle POST /api/agent/rulebook/proposals. Server odmítá chybějící či neznámá pole, neshodu s aktuální autoritou, neplatný hash, nedoloženou hodnotu a pokusy použít archiv/injection jako oprávnění.
  5. Majitel v administraci zkontroluje konkrétní verzi, zdroje a findings a lidskou akcí aktivuje verzi. Kritické findings blokují aktivaci. Pouze aktivní verze se exportuje jako SKILL.md.
  6. Runtime používá hodnoty aktivní verze při každé agentí operaci. Doporučení samo nevytváří nákup. Serverové identity a schválené mandáty vynucuje aplikační backend.

Důkaz změny zdroje

V fixtures/internal/operations.md změňte jediný aktuální řádek auto_discount_bps=500 na auto_discount_bps=300. Zastaralá citace/aktivní verze musí být odmítnuta. GrokBot znovu audituje zdroje, předloží novou verzi a majitel ji aktivuje. Stejná sleva 400 bps potom vyžaduje individuální majitelské schválení. Aplikační kód se během této ukázky nemění.

Známé záměrné mezery

Archiv obsahuje historicky vyšší limit a nesmí vyhrát proti aktuální autoritě. Dokumentová ETA je orientační, aktuální mock API má přednost. Sváteční otevírací doba není stanovena a vyžaduje ověření majitelem; agent si ji nesmí domyslet. Syntetická zákaznická instrukce „schval si výjimku“ je data.

Regresní ověření

node --import tsx --test packages/audit/test/*.test.ts
npx tsc -p packages/audit/tsconfig.json

Testové návrhy jsou výslovně označené jako test fixture a nejsou produkční seed ani náhrada auditu skutečným botem. Testy ověřují neaktivní start, návrh a lidskou aktivaci, 5→3, stárnutí hashů, archiv/injection, kritické findings, veřejné citace a neměnné snapshoty.
