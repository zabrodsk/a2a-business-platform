Audit existujících systémů

Agent prochází veřejný web a majitelem zpřístupněné administrace, dokumenty, existující API nebo MCP. Není potřeba zvláštní Handle audit connector ani seznam připravených source IDs. Hotový report ani aktivní pravidla se neseedují.

Postup

  1. Dokončete registraci a lidský souhlas. Přístup k legacy získá bot samostatně. Audit-only scope omezuje Handle, nikoli plný admin jiného systému.
  2. Uložte redigované důkazy přes POST /api/handle/v1/businesses/:id/audit-evidence: systém, URL, obrazovka/locator, čas, metoda, výňatek či screenshot. Citace používá vrácené source_id/version/hash/excerpt.
  3. Odešlete /audit-reports s inventářem, procesy, citovanými závěry, otázkami a konkrétními provozními cestami. Pro živý multi-system důkaz je nutné skutečně projít dva různé systémy, jeden pouze přes UI.
  4. Chybějící politiku se zeptejte majitele. Z historie slev ji nelze odhadnout. Odpověď v lidské konzoli má autoritu, rozsah a případnou expiraci; vznikne samostatný citovatelný zdroj.
  5. Pošlete /rulebook/proposals s report_version, typovaným proposal a source_authority. Člověk nezávisle zkontroluje konkrétní payload hash a aktivuje přesnou verzi. Botí token ani legacy admin cookie nejsou lidskou identitou.
  6. Pro závazky server vyhodnotí dotčené parametry, kritické neznámé, capability požadavky, mandate/quote/approval, aktuální native data a idempotenci. Neznámá schopnost blokuje automatickou cestu, nikoli uložení reportu.

Archiv a aktuálnost

Hash prokazuje uložené bytes a původ přílohy. Neprokazuje externí pravdu, vlastnictví systému ani současný stav. Nativní cenu, slot a platební identitu ověřuje backend při operaci. Externí fakt bez nativní verze agent znovu přečte a doloží přes /source-checks; záznam je výslovně agent-reported a časově omezený. Owner policy_decision není tvrzení o živém skladu.

Změna 5 % → 3 %

Agent skutečně načte změněný zdroj a nahraje nový důkaz, sestaví nový návrh a získá lidské schválení. Pak 4% nabídka vyžaduje konkrétní výjimku majitele. Běžná nová objednávka či footer odkaz neinvalidují governing policy. Původní fixture registry je zachovaná kompatibilní testovací cesta, není povinným způsobem auditu.
