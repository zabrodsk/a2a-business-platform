GrokBot tools for Pneu 007

The first integration is a bundled Node.js terminal client and a portable business skill. A native MCP/plugin can later wrap the same backend operations. This implementation does not install a plugin in a GrokBot account or deploy the autoshop.

Business GrokBot → authenticated HTTPS API → Express booking service → SQLite on persistent storage. The bot gets a business credential; the database file and staff credentials stay with the backend.

Setup on GrokBot

Supply the deployed business HTTPS origin and business token through the runtime's credential mechanism. Set PNEU007_BUSINESS_URL and PNEU007_TOOL_TOKEN on the bot's computer without putting token values in chat or shell arguments.

curl --fail --silent --show-error "$PNEU007_BUSINESS_URL/cli/garage.mjs" --output garage.mjs
curl --fail --silent --show-error "$PNEU007_BUSINESS_URL/skills/pneu007-business/SKILL.md" --output pneu007-business-SKILL.md
node garage.mjs tools
node garage.mjs --url "$PNEU007_BUSINESS_URL" sources

Ask the business bot to read and save the provided instructions as its business workflow. Native skill import is not assumed; verify the actual account's setup. Node.js 18+ is required. The backend also serves authenticated machine-readable metadata at GET /api/agent/tools.

Example requests

Price input:

{"service_spec":{"service_id":"tyre_change","vehicle_type":"personal","wheel_size_inches":18,"rim_type":"alu","runflat":false,"tpms":false,"wheel_count":4}}

Quote input:

{"slot_id":"slot-main","discount_bps":0}

Use the actual returned case, order and slot IDs. Source IDs come from the source catalog. Dates must describe future appointments for the current run. Times are returned with timezone information; use offset-qualified timestamps when filtering a Prague day.

Permissions and booking states

The business bot issues quotes and starts checkout. The customer bot creates the case and accepts a quote against its human-approved mandate. A human owner activates rules and decides exceptional discounts. The business tool package does not expose those human actions, staff cancellation/rescheduling, raw SQL or unrestricted database access.

Acceptance alone is not a confirmed reservation. Checkout creates a hold and payment intent. Only verified funding creates the confirmed booking. Order reads include saved payment, booking and receipt state. Reservation search excludes human-only and historical orders without assigned agent cases. Payment reconciliation remains on the backend.

Deployment and verification

Run the unified autoshop entrypoint apps/legacy/src/system.ts when using A2A plus booking tools. Put LEGACY_DB_PATH and LEGACY_RELAY_DB_PATH on Railway's persistent volume (for example /data/legacy.db and /data/legacy-relay.db). Supply production secrets and the actual public origin explicitly. The older relay deployment does not automatically gain these booking routes.

Local automated checks exercise real HTTP endpoints and the bundled client against isolated SQLite data and an explicitly simulated payment provider. These checks do not prove GrokBot account installation, public deployment, unattended wake-up or live Preprod payment interoperability.
