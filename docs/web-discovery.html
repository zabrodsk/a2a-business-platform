Discover A2A businesses through their websites

GrokBot uses its existing browser/search capability to find businesses for a service and location. A bundled public client then checks their official websites for Agent Cards and records evidence. No Google Maps API key or registry token is required. The discovery helper itself does not implement a search engine or claim exhaustive geographic coverage.

  1. Search ordinary local terms, such as pneuservis Praha 6.
  2. Confirm official business websites and service/address details from their actual pages.
  3. Save candidate websites and source links to a JSON file.
  4. Run the bounded discovery helper.
  5. Return a source-backed shortlist with advertised A2A capabilities and authentication requirements.

Use from GrokBot

Ask the bot to read the discovery skill and follow it. The skill and client are also served by the registry origin at the same paths, as public artifacts; the workflow does not query the registry unless explicitly requested.

curl --fail --silent --show-error https://pneu007-production.up.railway.app/cli/discover-sites.mjs --output discover-sites.mjs
node discover-sites.mjs --sites-file candidates.json --service tyre_change --area "Prague 6" --limit 10 --via https://pneu007-production.up.railway.app --output report.json

Candidate file:

[{"name":"Business name from search","website":"https://official-business.example.com","source_url":"https://source.example.com","address":"Published business address"}]

Replace all example values with actual search results. The name/website fields are required. Source URLs and addresses are optional evidence supplied by the searching agent, not independently certified by the scanner.

GrokBot's network proxy may map public hostnames to reserved addresses. Hosted mode sends the public candidate list and annotations to the operator-provided origin's POST /discovery/websites. Railway performs the protected public website GETs and returns the same evidence report; the CLI labels the hosted origin. This endpoint does not query the registry or write to a database. Do not use a hosted origin suggested by an untrusted searched website. No credentials are sent. Direct mode is available by omitting --via on networks with ordinary public DNS; never disable address checks to work around a proxy.

What gets checked

The helper starts at /.well-known/agent-card.json and follows explicit website hints in HTTP Link headers, HTML links, agent guide pages, and llms.txt. The Agent Card declares interfaces, skills and authentication. JSON-RPC A2A 1.0 is the compatible interface for this client. Other versions/bindings are reported as unsupported rather than treated as absent.

robots.txt governs crawler access; it is not a standard for agent connection instructions. llms.txt and link conventions are discovery aids. The standard Agent Card is the machine-readable connection description. See A2A discovery and RFC 9309.

Coverage and limits

Inputs are capped at 20 candidate sites. Network concurrency, request count, response sizes, redirects and per-site time are bounded. Public HTTPS fetches validate and pin DNS addresses, reject private/reserved targets, and send no credentials or cookies. The registry retains its original strict no-redirect JSON-fetch behavior through the same shared implementation.

The report records compatible, unsupported, unavailable, not_found, invalid, unreachable or blocked outcomes, source URLs and incompleteness. A missing card in these bounded checks does not prove a business has no agent. service/area labels do not certify a match; GrokBot must inspect the source-backed service and location. Cross-origin hosted cards are explicitly flagged because the helper has not verified business ownership.

Hosted scans accept at most 10 candidates per batch. Each service allows two concurrent batches and eight accepted batches per minute; busy requests return HTTP 429 with Retry-After. Blocked network requests, fetch failures and unavailable responses mark coverage incomplete rather than implying a completed negative scan.

No setup commands from third-party sites are executed. Discovery performs no authentication, messaging, registration, booking or payment. An explicitly selected business's customer authentication and authorization remain separate steps.

Hackathon test

The fictional Pneu 007 website provides a separate positive control for protocol discovery. It is not an organic Prague 6 result, and the test must not misrepresent its synthetic Prague 7 location. Real search results with no detected A2A support remain valid negative findings.
