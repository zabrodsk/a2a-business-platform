Pneu 007 a Handle

Web, objednávky, kalendář, dummy data a supplier mocks fungují nezávisle na agentovi. Handle přidává registraci, doložený audit, samostatná lidská schválení, spravovaný relay, MCP a předání runtime.

Lokální první den

npm ci
npm run typecheck
npm test
HANDLE_FRESH=true npm run start:system

Výchozí URL http://127.0.0.1:8797. Fresh režim neseeduje firmu, agentí vazbu, relay, audit ani aktivní rulebook. Použijte nový LEGACY_DB_PATH a LEGACY_RELAY_DB_PATH; fresh flag nemaže existující data. V přetrvávající DB zůstávají identity a revokace.

Vývojové přístupy k legacy jsou v privátním data/legacy-access.json; oddělený setup credential prvního člověka v data/handoru-access.json, oba mode 600 a mimo Git. Botovi dejte pouze konkrétní auditní přístup, nikdy celý soubor s lidskými secrets. První člověk založí vlastní Handle účet na /handle. Legacy admin cookie nezpřístupní lidské approval.

Produkční konfigurace

Nastavte NODE_ENV=production, skutečné LEGACY_PUBLIC_URL, trvalé cesty obou DB, legacy owner/staff/customer hesla, customer-agent tokeny a LEGACY_RELAY_ADMIN_TOKEN. V režimu HANDLE_FRESH=true není business-agent environment token potřeba. První lidský účet vyžaduje samostatné HANDLE_OWNER_SETUP_SECRET. Žádné tajemství nevkládejte do Git, webu, karty ani promptu.

Konfigurace bez fresh flagu jednorázově importuje starý business credential pouze jako hash. Bez schváleného rulebooku je audit-only. S předchozím aktivním rulebookem zachová kompatibilní provoz. Odvolání či rotace se při restartu nepřepíše environment tokenem. Kompatibilní relay migruje stejné task/work/reply IDs do firmy Pneu.

HANDLE_RELAY_PUBLIC_URL může označit druhý HTTPS origin, který směruje /relay/:id/* do téže managed služby. Každá firma má vlastní relay SQLite soubor vedle legacy DB. Domény musí být skutečně dostupné; konfigurace je neprovisionuje v externím DNS. V fresh režimu jsou původní /a2a/jsonrpc a /bot vypnuté.

Průchod

Dejte botovi /.well-known/handle.json a onboardingové instrukce. Registrace → website challenge → nezávislý lidský souhlas → vlastní auditní účet → relay → skutečný audit → přesná lidská aktivace → private probe → provozní grant → card publication/verify. Nový účet používá /mcp nebo stejné HTTP operace. Pro mutace zachovejte původní Idempotency-Key.

Majitel před výměnou skutečně rotuje starý Pneu auditní admin účet a odhlásí jeho sessions. U externích systémů doloží jejich vlastní revokaci a dohledání nejistých zápisů. Pending znamená pending. Přijaté nativní operace a platební intent přežijí výměnu; backend nepošle nové inkaso.
