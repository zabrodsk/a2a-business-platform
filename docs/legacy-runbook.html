Pneu 007: funkční legacy business

Samostatný web, backend, objednávky, kalendář, auditní zdroje a A2A transport. Veřejný web používá dodaný Claude Design; skutečné aplikace načítají a zapisují data do SQLite. Firma, osobní údaje a fyzická služba jsou fiktivní.

Spuštění

npm ci
npm run typecheck
npm test
npm run start:system

Výchozí adresa je http://127.0.0.1:8797. Pokud ji obsadí jiný program, použijte LEGACY_PORT a odpovídající LEGACY_PUBLIC_URL. Server v takovém případě končí chybou; neohlásí falešné spuštění. Legacy bez A2A lze spustit npm run start:legacy. Původní samostatný relay nadále používá npm start.

Přihlášení a soukromé údaje

Vývojové spuštění vygeneruje silné přístupové údaje v data/legacy-access.json s oprávněním 600; soubor je mimo veřejný web a gitignored. Uživatelská jména: customer-a, customer-b, staff, owner. Hesla ani agentí tokeny nepublikujte. Zákazník schvaluje pouze vlastní mandát; majitel firemní pravidla a konkrétní výjimky. Botí token nemůže založit lidskou session ani se vydávat za člověka.

Produkční režim vyžaduje explicitní privátní environment: LEGACY_OWNER_PASSWORD, LEGACY_STAFF_PASSWORD, LEGACY_CUSTOMER_A_PASSWORD, LEGACY_CUSTOMER_B_PASSWORD, LEGACY_BUSINESS_AGENT_TOKEN, LEGACY_CUSTOMER_AGENT_A_TOKEN, LEGACY_CUSTOMER_AGENT_B_TOKEN a LEGACY_RELAY_ADMIN_TOKEN. Volitelný LEGACY_OWNER_AGENT_TOKEN má pouze interní read-only finanční report. Nastavte skutečnou HTTPS LEGACY_PUBLIC_URL a připojte trvalý disk pro obě DB; web a A2A pak běží na stejné doméně se stejnými agentími identitami. Kontejner: Dockerfile.legacy; neobsahuje lokální secrets ani DB.

Ověření z prohlížeče

  1. Otevřít kalkulátor: výchozí 18″ alu přezutí = 2 472 Kč; TPMS = 2 872 Kč. Cena je výstup skutečné společné cenové funkce.
  2. Odeslat nezávaznou poptávku; vrátí inquiry ID bez rezervace a platby.
  3. Přihlásit customer-a, otevřít objednání, vybrat volný slot a potvrdit zálohu nebo dostupnou plnou úhradu. Kontaktní údaje se uloží ke konkrétní objednávce.
  4. Ověřit potvrzenou rezervaci, doplatek, samostatný platební stav a stažení ICS. Defaultní local_demo je výslovná simulace s demo: hashem; nejde o blockchainovou platbu.
  5. Přihlásit staff/owner v /admin; objednávka se objeví v provozu i kalendáři. Zobrazit zákazníky, sklad, dva mock partnery a jejich aktuální ETA/RFQ historii.
  6. V /handoru jsou zdroje, návrhy pravidel, schválení, mandáty a skutečné události. Při prvním spuštění není aktivní rulebook.

Audit je práce skutečného GrokBota

Bot obdrží vlastní omezený token a nástroje, nikoli hotové odpovědi. Čte čtyři stránky, tři interní soubory a pseudonymizované systémové snapshoty. Návrh s citacemi posílá přes /api/agent/rulebook/proposals. Majitel jej uvidí vedle zdrojů a může aktivovat pouze podporovanou a aktuální verzi. Příkazy vložené do zdrojů neudělují oprávnění. Backend negeneruje audit za model.

Původní provozní zdroje povolují pro agentí nákup pouze masumi/Preprod. Lidský local_demo nákup funguje nezávisle; prokazuje legacy systém, nikoli aktivovaný agentický Masumi průchod. Automatické testy používají vlastní izolované auditní fixtures označené testem. Nejsou vydávány za provedený GrokBot audit.

Trvalá data a bezpečný reset

Business DB je v data/legacy.db; relay DB v data/legacy-relay.db. Restart zachová historii i rozpracované platby. Reset je majitelská operace a odmítne live Preprod záznamy i nejisté/nedokončené platby. Lokální fixture reset nikdy nemaže chain historii. Zdrojové soubory se nevracejí automaticky na původní slevy. Pro čistý experiment lze zvolit nový, explicitní LEGACY_DB_PATH a LEGACY_RELAY_DB_PATH.

Testování a testovací hranice

npm test zahrnuje původní relay, skutečné SDK HTTP spojení, domain, audit, autorizační API a platební provider fixtures. npm run typecheck kontroluje všechny workspace. npm run build vytváří samostatná CLI a2a.mjs, inbox.mjs a garage.mjs. Živý Preprod proof je samostatný test s reálnými účty a prostředky; zelené unit testy jej nenahrazují.
