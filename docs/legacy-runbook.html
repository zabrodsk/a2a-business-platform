Pneu 007 a Handle

Web, objednávky, kalendář, dummy data a supplier mocks fungují nezávisle na agentovi. Handle přidává registraci, doložený audit, samostatná lidská schválení, spravovaný relay, MCP a předání runtime.

Lokální první den

npm ci
npm run typecheck
npm test
HANDLE_FRESH=true npm run start:system

Výchozí URL http://127.0.0.1:8797. Fresh režim neseeduje firmu, agentí vazbu, relay, audit ani aktivní rulebook. Použijte nový LEGACY_DB_PATH a LEGACY_RELAY_DB_PATH; fresh flag nemaže existující data. V přetrvávající DB zůstávají identity a revokace.

Vývojové přístupy k legacy jsou v privátním data/legacy-access.json; oddělený setup credential prvního člověka v data/handoru-access.json, oba mode 600 a mimo Git. Botovi dejte pouze konkrétní auditní přístup, nikdy celý soubor s lidskými secrets. První člověk založí vlastní Handle účet na /handle. Legacy admin cookie nezpřístupní lidské approval.

Produkční konfigurace

Nastavte NODE_ENV=production, skutečné LEGACY_PUBLIC_URL, trvalé cesty obou DB, legacy owner/staff/customer hesla, customer-agent tokeny a LEGACY_RELAY_ADMIN_TOKEN. V režimu HANDLE_FRESH=true není business-agent environment token potřeba. První lidský účet vyžaduje samostatné HANDLE_OWNER_SETUP_SECRET. Žádné tajemství nevkládejte do Git, webu, karty ani promptu.

Konfigurace bez fresh flagu jednorázově importuje starý business credential pouze jako hash. Bez schváleného rulebooku je audit-only. S předchozím aktivním rulebookem zachová kompatibilní provoz. Odvolání či rotace se při restartu nepřepíše environment tokenem. Kompatibilní relay migruje stejné task/work/reply IDs do firmy Pneu.

HANDLE_RELAY_PUBLIC_URL může označit druhý HTTPS origin, který směruje /relay/:id/* do téže managed služby. Každá firma má vlastní relay SQLite soubor vedle legacy DB. Domény musí být skutečně dostupné; konfigurace je neprovisionuje v externím DNS. V fresh režimu jsou původní /a2a/jsonrpc a /bot vypnuté.

Průchod

Dejte botovi /.well-known/handle.json a onboardingové instrukce. Registrace → website challenge → nezávislý lidský souhlas → vlastní auditní účet → relay → skutečný audit → přesná lidská aktivace → private probe → provozní grant → card publication/verify. Nový účet používá /mcp nebo stejné HTTP operace. Pro mutace zachovejte původní Idempotency-Key.

Majitel před výměnou skutečně rotuje starý Pneu auditní admin účet a odhlásí jeho sessions. U externích systémů doloží jejich vlastní revokaci a dohledání nejistých zápisů. Pending znamená pending. Přijaté nativní operace a platební intent přežijí výměnu; backend nepošle nové inkaso.

Lidská administrace

/admin nabízí přehled provozu, hledání a filtrování objednávek, kalendář v pražském čase, zákazníky, sklad a dodavatele. Detail zakázky ukazuje běžné informace; původní technický záznam je rozbalovací. Změna termínu, storno, refund a úprava skladu používají stávající chráněná API. Platební žádost, escrow, výplata a provedení služby jsou odlišené. Zákaznická schvalovací UI zůstávají samostatná.

Provoz GrokBota používá vlastní povolený servisní přístup přes /mcp nebo stejné HTTP API. Lidské UI není podmínkou těchto operací; při auditu lze stále pozorovat dostupná UI. Skutečná podpora MCP v konkrétním runtime se dokládá samostatně.

Veřejné demo údaje

Kontakt, otevírací dobu, fiktivní plánek a vysvětlení plateb skládá server při načtení stránky z veřejného profilu a stávající booking/platební konfigurace. Služby, kalkulátor, kontakt a podmínky používají stejný serverově vykreslený header včetně přímých .html adres. Navigace, aktivní stránka a rozložení přihlášení sdílejí společné styly. Původní HTML šablony zůstávají beze změny jako kompatibilní podklady dřívějšího schváleného auditu. Jejich archivní hash neprokazuje obsah nově vykreslené stránky; fresh audit čte skutečný web/API a ukládá nové důkazy. Tato prezentační změna neaktivuje nový rulebook ani nemění obchodní limity.

Storno a audit plateb

Aktuální obchodní politika je veřejná na /cancellation-policy.json a /podminky#storno. Obsahuje bezplatné storno neprovedené služby, výši vrácení a lidské provozní lhůty; nepředstírá automatické refundy ani nové oprávnění agenta. U konkrétní platby je rozhodný její provider/síť a ověřené pozorování. Aktuální /api/payments/config je konfigurace nových nativních plateb. Historické importy a samostatný lokální /demo/* tok neurčují celé platební prostředí.

Freshaudit čte skutečně vykreslený web a příslušný firemní kontext, ne historický HTML archiv nebo cizí připravený rulebook. Exporty původních webových šablon uvádějí representation=template_archive; jejich current znamená aktuální verzi tohoto archivu, nikoli aktuální vykreslenou stránku. Publikovaná politika má vlastní zdroj web-cancellation-policy a representation=published_document. Původní hash/verze schválených podkladů a validace oprávnění zůstávají stejné. Generické instrukce v GrokBot-Onboarding.md rozlišují modelovou firmu, reálnou Preprod transakci a lokální simulaci. Masumi refund okna a role vycházejí z dokumentace Masumi; tato obchodní politika negarantuje síťové vypořádání do tří dnů.

Ověření a omezení
