Railway nasazení Pneu 007

Projekt pneu007-business v osobním workspace Dusan Zabrodsky's Projects. Veřejná aplikace: pneu007-production.up.railway.app.

Projekt ID 64bc1351-eac4-4b62-872c-60cc3e42b7df; služba pneu007, ID 21be6bf8-d223-487a-8613-6f8906f9cb30; prostředí production ff6f43ee-8c9c-4c09-831b-dae34d5d6dcf. Trvalý volume pneu007-volume je na /data a uchovává oddělené legacy.db a legacy-relay.db. Původní pneu007-relay je jiný projekt.

Build a runtime

Služba používá Dockerfile.legacy, zvolený přímo v nastavení této Railway služby a proměnnou RAILWAY_DOCKERFILE_PATH. Toto nastavení nevybírá původní root Dockerfile pro samostatný relay. Server naslouchá na PORT=8080 a 0.0.0.0. Healthcheck je /healthz, jedna replika pro SQLite. LEGACY_PUBLIC_URL je veřejná HTTPS doména; cookies jsou Secure/HttpOnly/SameSite=Strict. Healthcheck, timeout 180 sekund, jedna replika a restart ON_FAILURE jsou uložené v nastavení služby. Nepoužívá se zastaralý Config as Code soubor.

GitHub synchronizace

Veřejný repozitář zabrodsk/pneu007-business, větev main, slouží jako zdroj kódu. Railway je propojené s touto větví pro automatický build a deployment při pushi. GitHub Actions samostatně spouští typecheck a testy. Konkrétní úspěch automatického deploymentu se ověřuje vůči SHA commitu.

Lokální změny se synchronizují standardním git add → git commit → git push origin main. Necommitnuté soubory se automaticky nepublikují. Push kódu nenahrazuje databázi; její data zůstávají na volume. Secrets se spravují v Railway Variables, ne v GitHub historii.

Přístupy

Uživatelská jména: owner, staff, customer-a a customer-b. Pro toto nasazení byly vytvořené samostatné silné přístupy. Soukromý lokální soubor data/railway-access.json obsahuje jejich hodnoty; je gitignored, není součástí Docker image ani veřejného repozitáře. Produkční údaje se nesmějí kopírovat do README, screenshotů, auditních zdrojů ani promptů.

Platební režim a agenti

Nasazení používá výslovně označený local_demo. Nasazení není důkaz Masumi on-chain platby. Masumi Preprod připojit podle návodu, oddělit funding/result/payout a zajistit wallet lifecycle. Při prvním nasazení není aktivní rulebook: skutečný firemní GrokBot má auditovat web a soukromé zdroje a majitel jej má následně schválit.

Provozní ověření

Po nasazení ověřit HTTPS web, session, zákaznickou objednávku, kalendář a ICS, přístup majitele, zákaz čtení cizích dat a privátní auditní podklady. Testovací slot zvolit mimo slot-main pro zachování hlavního agentického dema. Po restartu musí zůstat stejné order/booking ID na trvalém disku. Soubory se nesmějí resetovat kvůli běžnému redeployi.
