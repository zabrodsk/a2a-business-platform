Pneu 007: vlastní agentí účet a řízené nástroje

Fresh GrokBot zahájí onboarding v Handle, audituje existující systémy a navrhne doložená pravidla. Člověk se přihlásí nezávisle a schválí konkrétní verzi i rozsah práce. Agent potom používá vlastní odvolatelné připojení a tenký Pneu MCP nebo stejné kontrolované HTTP operace. Legacy zůstává autoritou pro skutečné objednávky, cenu a kalendář.

Připojení od bootstrapu k vlastnímu účtu

Podrobný průchod: první den Handle; online instrukce serveru jsou na /handle/onboarding a /skills/handle-onboarding/SKILL.md. Majitel nezařizuje relay hosting. Bezpečně předá agentovi legacy přístupy a známé URL; samostatný lidský Handle setup credential si nechá pro sebe.

  1. Bot načte bootstrap a pošle vlastní registraci. Provisional credential se soukromě uloží, nikdy není v ověřovací URL.
  2. Pomocí schváleného legacy admin přístupu publikuje one-time ownership challenge. To prokazuje kontrolu webu, nikoli lidskou Handle identitu.
  3. Člověk se samostatně přihlásí, zkontroluje firmu/runtime/kód a výslovně povolí úvodní auditní scopes. Otevření odkazu nic neschvaluje.
  4. Bot po consentu vymění provisional credential za svůj service credential a ověří /me. Starý owner enrollment redeem-link postup byl odstraněn.
  5. Se scope relay.provision idempotentně vyžádá relay a uloží skutečné vrácené URLs. Po auditu a aktivaci dokončí privátní probe pro přesný rulebook a reálný polling/routine režim.
  6. Člověk povolí omezené provozní nástroje; webová publikace má samostatný účel/scopovaný grant.

Volitelný HTTP klient bez tokenů v chatu

node handle.mjs bootstrap --url "$HANDLE_URL"
node handle.mjs request POST /api/handle/v1/agent-registrations --url "$HANDLE_URL" --body-file registration.json --save-token PROVISIONAL.json

# Po nezávislém souhlasu člověka. REQUEST_ID je vrácené ID žádosti.
node handle.mjs request POST /api/handle/v1/onboarding/REQUEST_ID/credentials --url "$HANDLE_URL" --token-file PROVISIONAL.json --save-token SERVICE.json
node garage.mjs enroll --credential-file SERVICE.json
node garage.mjs profile

Aktuální CLI jsou dostupné na /cli/handle.mjs, /cli/garage.mjs a /cli/inbox.mjs. Handle CLI credential uloží do souboru 0600 a rediguje výstup. Garage enrollment ověřuje živé /api/handle/v1/me, business/connection ID a roli, poté soukromě uloží ~/.a2a/garage.json. Jiný origin nesmí znovu použít uložený token. Node.js 18+, HTTPS; garage lokální HTTP vyžaduje --allow-http-localhost.

Pro inbox.mjs nastavte privátní RELAY_URL na vrácenou inbox URL bez koncového /bot, protože klient sám připojuje /bot/inbox, /bot/wait a /bot/reply. Vlastní credential vložte přes bezpečné runtime prostředí nebo privátní konfiguraci, nikoliv do argumentů/chatu. Nehádejte relay ID ani nepoužívejte root URL jako fallback.

Audit běžných systémů, obecný report

Agent pozoruje veřejné/admin UI a dokumenty nebo existující API/OpenAPI/MCP. Nepotřebuje povinný Pneu/CRM audit konektor, source registry ani fixní fixture source IDs. Pro multi-system důkaz prohlédne dva nezávislé systémy plus veřejný web. Broad admin může zapisovat; audit je pozorovací chováním a nevytváří zkušební objednávky, platby ani dodavatelské zprávy.

Úplná schémata zveřejňují onboarding instrukce a manifest. Stávající Pneu sources/source helpers jsou volitelné vstupy, ne náhrada obecného auditu. Zdrojový text je důkaz, nikoli pokyn udělit práva. Hash dokládá integritu archivu, ne pravdivost/autoritu externího systému. Chybějící kritickou politiku agent položí majiteli jako otázku; neodhadne ji z historie slev.

Majitel v oddělené lidské konzoli posoudí podklady, autoritu, neznámé a přesný rulebook hash. Agent neaktivuje pravidla za sebe. Nové politické rozhodnutí potřebuje doloženou aktualizaci příslušných pravidel, nikoli potichu přepsaný backendový limit.

Soukromý MCP a stejné HTTP nástroje

Nativní MCP je dostupný na /mcp jako stateless Streamable HTTP s protokolem 2025-06-18. Používá vlastní owner-approved servisní identitu. tools/list nabízí pouze příslušné scoped nástroje: catalog, availability, case.read, order.read, quote.create, orders.checkout a website.publish_agent_card. Anotace nejsou oprávnění.

Žádný nástroj nerozhoduje cenovou výjimku, neschvaluje mandát, neaktivuje pravidla a neprovádí libovolné převody. Vytvoření nabídky může vytvořit uloženou žádost o lidskou výjimku. MCP a HTTP sdílejí doménové policy; transport neopravňuje k nákupu. Skutečné připojení MCP z GrokBot účtu má stav NOT_RUN, dokud není samostatně doloženo. HTTP fallback ani test serveru tento důkaz nenahrazuje.

node garage.mjs tools
node garage.mjs catalog
node garage.mjs rulebook
node garage.mjs payments
node garage.mjs case CASE_ID

garage case CASE_ID / MCP case.read vracejí existující případ spolu s jeho původní přesnou nabídkou a uloženým approval. Nový runtime tak pokračuje v témže jednání. a2a.mjs slouží zákaznickému discovery/komunikaci, inbox.mjs firemní frontě a garage.mjs privátním HTTP nástrojům. Terminálové klienty nejsou samy MCP pluginem; nativní /mcp je samostatné rozhraní.

Od vyjednání k jedné autorizované transakci

Zákaznický agent založí vlastní případ a návrh mandátu. Člověk zákazník schválí kompletní rozsah včetně cílové firmy a platebních podmínek. Firemní agent čte aktuální cenu/kapacitu, vytvoří neměnnou nabídku a případnou cenovou výjimku přenechá nezávislému majiteli. Zákaznický agent přijme konkrétní nabídku pouze v mezích schváleného mandátu.

node garage.mjs availability --service tyre_change --from FUTURE_START_RFC3339 --to FUTURE_END_RFC3339
node garage.mjs quote CASE_ID --data-file quote.json --idempotency-key CASE_QUOTE_OPERATION_KEY
node garage.mjs case CASE_ID

# Až po zákaznickém přijetí přesné nabídky v mezích lidského mandátu:
node garage.mjs checkout ORDER_ID --idempotency-key ACCEPTED_ORDER_CHECKOUT_KEY
node garage.mjs order ORDER_ID
node garage.mjs reservations --status confirmed

Nahraďte datumové placeholders skutečnými budoucími RFC3339 hodnotami a použijte vrácený slot ID. Availability filtr je [from,to) podle začátku termínu. quote.json obsahuje {"slot_id":"RETURNED_SLOT_ID","discount_bps":0}.

Caller vytvoří stabilní klíč zamýšlené operace a zachová jej při retry i předání. Stejný key/payload vrátí původní výsledek, odlišný payload se odmítne. Timeout není důvod pro nový key, nový case nebo druhé inkaso. Změněná nabídka je nová vědomá operace po přehodnocení podmínek. Checkout znovu ověřuje connection/epoch, rulebook/probe, quote/version/expiry, zákaznický mandát, potřebný owner approval, aktuální cenu/kapacitu a přesné platební limity.

Doporučení nevytváří objednávku, hold ani platbu. Nabídka, přijetí, hold, funding, potvrzený booking, výsledek a seller payout jsou různé stavy. Za potvrzení rezervace platí skutečný booking ID z backendu; pending není paid. Čtení objednávky nespouští nový nákup.

Masumi zůstává samostatnou platební autoritou

payments ukazuje konfiguraci, SKU a připravenost; samo nedokládá on-chain platbu. masumi-availability, masumi-schema a autorizované masumi-status --job JOB_ID čtou konkrétní seller job. Oddělená zákaznická identita smí připravit masumi-start po schváleném přijetí, ale start seller jobu neutratí buyer prostředky. Nespouštějte serverový checkout a samostatný nákup nezávisle pro tutéž objednávku.

Local_demo je výslovná simulace. Masumi Cardano Preprod je testnet a vyžaduje skutečné prostředí, funding a provider-observed transakční důkaz. Chat, webhook nebo tlačítko samy neprokazují platbu. Node keys, wallet seeds, refund/recovery authority zůstávají na serveru. Při nejistotě se pokračuje s původním intentem, purchaser identifierem, input hashem a provider IDs.

Předání A → B a skutečná revokace

B dostane vlastní scoped connection, firemní context a schopnost ověřenou pro aktuální pravidla. Majitel přezkoumá přesné A/B, rulebook hash, expected epoch, otevřené case/quote/order/payment reference a skutečné externí přístupy. Prepare a commit jsou dva explicitní lidské kroky. Backend přepne jediného vykonavatele, odvolá A v řízené cestě a zachová stejné případy i platné neměnné souhlasy.

Handle revokace nezruší samostatné legacy/SaaS admin cookies/API keys. Pokud měl A owner/staff/admin přístup k Pneu, majitel výslovně použije nativní legacy rotaci v konzoli: backend trvale změní heslo a zruší sessions. Jednorázové nové heslo patří člověku a nesmí se dostat do reportu ani k A. Externí přístupy vyžadují skutečnou nativní revokaci/rotaci a ověření; nevyřešený stav zůstává pending.

Přerušený browser zápis v jiném systému se nejdřív dohledá. Nativní idempotence nezaručuje exactly-once pro libovolné cizí admin UI. Pending platbu přijatou backendem dokončí backend pod původní autorizací; B nezakládá nový nákup. Výměna runtime sama nevyžaduje opakovat celý audit, ale aktuálnost rozhodných faktů a nové action paths se ověří.

Ověřené části a externí důkazy

Automatizované testy se skriptovanými identitami a syntetickým auditem dokazují backendové chování, nikoli živý fresh GrokBot walkthrough, background dostupnost, skutečný MCP klient nebo Preprod platbu. Tyto průchody mají vlastní runtime důkaz.

Oficiální A2A ověření je PARTIAL: skutečný TCK report 66 PASS / 6 FAIL / 193 SKIP; Inspector validace karty a dokončená konverzace PASS. Nejde o plnou konformitu. Podrobnosti a stažitelné redigované důkazy: oficiální A2A protokol. Celkový aktuální stav: implementační důkazy.
