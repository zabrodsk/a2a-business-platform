Pneu 007: přístup agentů k demo businessu

Web, autentizované provozní nástroje a stávající A2A relay běží na stejném originu. Firemní bot čte legacy systém, předloží vlastní audit a rulebook, po schválení majitelem obsluhuje skutečné objednávky demo provozovny. Žádný endpoint nevytváří za bota předstíranou odpověď nebo automatický audit.

Co je A2A a co jsou soukromé nástroje

RozhraníÚčelIdentita

/bot/inbox, /bot/wait, /bot/replySoukromá fronta pro skutečného firemního GrokBota. Bot přečte zprávu, použije provozní nástroje a sám odešle odpověď do původního A2A tasku.Stejný firemní token jako u legacy nástrojů. Toto HTTP API není A2A.
/api/audit/…, /api/agent/…Autentizované interní nástroje pro audit, případy, nabídky a autorizovaný checkout. Nejsou zákaznickým A2A endpointem.Server odvozuje roli a zákazníka z tokenu; tělo požadavku nemůže nastavit privilegia.

Regresní test používá skriptované identity a zřetelně označený testovací návrh rulebooku. Prokazuje implementovaný transport a policy gates. Přístup ke dvěma reálným účtům GrokBot, audit skutečným modelem a veřejná interoperabilita vyžadují samostatný runtime důkaz.

Spuštění a identity

npm run build
node --env-file-if-exists=.env.legacy.local --import tsx apps/legacy/src/system.ts

Výchozí lokální origin je http://localhost:8797. LEGACY_PUBLIC_URL musí odpovídat URL, kterou budou agenti skutečně otevírat. Samostatný legacy server a původní samostatný relay lze dál spouštět odděleně; sjednocený systém používá vlastní relay databázi a nemění původní produkční profil.

Vývojové přístupové údaje vznikají lokálně v data/legacy-access.json s oprávněním 0600. Produkce vyžaduje explicitní secrets. Předávejte tokeny přímo do prostředí příslušného bota, bez veřejných dokumentů, chatů nebo logů. Jednotný systém vypíná relay enrollment, aby nevznikaly další tokeny bez stejné identity v legacy nástrojích.

Audit a schválení rulebooku

  1. Firemní GrokBot otevře veřejné stránky a autentizovaný GET /api/audit/sources.
  2. Stáhne povolené zdroje přes GET /api/audit/export/:sourceId, skutečné provozní snapshoty a mock dodavatelské údaje. Zkontroluje verze, autoritu, rozpory a nejasnosti. Poznámka zákazníka ani archivní politika nesmějí udělovat pravomoci.
  3. Bot samostatně předloží návrh přes POST /api/agent/rulebook/proposals s profilem businessu, parametry, nálezy a citacemi konkrétních zdrojů. Server validuje jejich hash, verzi a podporu pravidla v citovaném obsahu.
  4. Majitel návrh zkontroluje a aktivuje v lidské konzoli. Firemní agent ani transportní admin nemohou toto lidské rozhodnutí nahradit.
  5. Agent Card a A2A obsluha jsou poté dostupné. Změna autoritativního podkladu zneplatní starou politiku a vyžaduje nový audit a schválení.

Kalendář, historie objednávek, ledger a dva mock dodavatelé jsou provozní důkazy; jejich běžné změny samy o sobě nejsou změnou autoritativní politiky. Pozorování se ukládají jako verzované auditní snapshoty. Dodavatelská rozhraní zůstávají v demo systému a neodesílají skutečný nákup externím partnerům.

Terminálové nástroje

a2a.mjs slouží zákaznickému botovi pro discovery a komunikaci. inbox.mjs slouží firemnímu botovi pro čtení a odpovědi ve frontě. garage.mjs je generický klient soukromých HTTP nástrojů; endpoint businessu neurčuje zákaznickému A2A klientovi.

# Token je dodaný do prostředí, jeho hodnota se netiskne.
node packages/agent-client/dist/garage.mjs --help
node packages/agent-client/dist/garage.mjs --url https://BUSINESS_ORIGIN call GET /api/audit/sources
node packages/agent-client/dist/garage.mjs --url https://BUSINESS_ORIGIN call POST /api/agent/cases --data-file case.json

# Pouze při lokálním vývoji; HTTP jinde je zakázáno.
node packages/agent-client/dist/garage.mjs --url http://localhost:8797 --allow-http-localhost call GET /api/audit/sources

CLI čte PNEU007_TOOL_TOKEN. Vyžaduje explicitní origin, výchozí HTTPS a odmítá přesměrování. JSON payload pochází ze souboru; token nepatří do argumentů příkazu. Nástroj nepřidává podnikatelskou logiku ani negeneruje schválení.

Zákaznický bot kontaktuje firemního přes A2A, vyjednají konkrétní nabídku. Provozní nástroje ukládají případ, neměnnou verzi nabídky a její vazbu na aktivní rulebook. Zákazník jako člověk schválí omezený mandát se službou, cenou, zálohou, deadlinem, platební sítí, příjemcem, množstvím assetu a limitem poplatku. Zákaznický agent přijme konkrétní nabídku; firemní agent následně vytvoří checkout pouze v těchto mezích.

Režim doporučení nevytváří objednávku ani platbu. Vyšší sleva vyžaduje lidské schválení konkrétní neměnné nabídky. Rezervace je potvrzená po ověření skutečného platebního stavu a zápisu kalendáře; duplicitní odpověď nebo retry nesmí vytvořit druhou rezervaci.

Lokální local_demo platba je simulace a má toto označení v UI i ledgeru. Masumi je oddělený provider na Cardano Preprod; bez skutečně nakonfigurovaného payment service, peněženek a ověřené testnet transakce nelze tvrdit, že proběhla on-chain platba. Příchozí webhook sám nesmí měnit objednávku na zaplacenou.
